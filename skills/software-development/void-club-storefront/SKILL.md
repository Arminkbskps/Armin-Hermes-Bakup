# VOID CLUB Storefront Development

VOID CLUB is the user's dark streetwear e-commerce app rooted in `D:/Hermes file`:
FastAPI backend (`backend/app/`), vanilla HTML/CSS/JS frontend (`frontend/`), served together by `run_server.py` on port 8000. Python deps live in `D:/Hermes file/.venv`. Brand: accent `#990000`, dark glassmorphism, Vazirmatn/Outfit, order codes `VOID-XXXXX`.

## Non-negotiable workflow rules

0. **NEVER INVENT FAKE PRODUCTS, DROP LIMITS, OR IMAGINARY ACCESSORIES FOR MARKETING.** VOID CLUB is an active live e-commerce store (`voidclubs.ir`) with real products across categories (Cinema & Series / Better Call Saul & Breaking Bad, Anime & Manga, Rock & Metal Music, Gaming). For any marketing, reel script, promo video, or strategic proposal, ALWAYS query the live storefront or API (`/api/products`) first. Pull real titles, subtitles, prices, and actual product mockups. Never invent imaginary concepts like "exclusive 50-piece drop" or "metal VIP cards" out of thin air.

1. **NEVER redesign the header, hero slider, or site-wide chrome unprompted, and NEVER alter brand colors or visible styling to satisfy automated audit tools.** The user guides visual redesigns step-by-step and supplies reference sites/screenshots themselves. A proactive 7wears-style header rebuild across 9 files was fully rejected and rolled back. Similarly, NEVER alter brand colors (such as changing `#990000` to `#ff3344` to satisfy Lighthouse color contrast audits) or modify visible design elements to chase audit numbers («از لحاظ ظاهری گفتم که هیچ تغییری ایجاد نشه ها»). Brand red `#990000` is strict and inviolable. Achieve 95-100 scores exclusively through zero-visual-impact structural improvements (ARIA labels, TCP 14KB window inlined CSS, image

2. **NEVER invent fictional business models, synthetic passes, or imaginary limited club caps for VOID CLUB without checking the live store.** VOID CLUB is a dark streetwear apparel store with real collections in Cinema & TV (e.g. Better Call Saul, Breaking Bad, Lalo Salamanca), Anime & Manga, Rock Music, and Gaming. Always inspect live products, mockups, and descriptions via `https://voidclubs.ir/api/products` before generating promo assets, video scripts, or copy. byte optimization, font-face range mapping). Correct sequence: propose design in chat → get explicit approval → change ONE page/file at a time with checkpoints.
2. **Stage multi-file work as a todo list and execute in small verified steps.** Big-bang edits across many files trigger "همه چیز رو خراب کردی" rollbacks. Once the plan/todo is approved, work through it autonomously WITHOUT pausing for re-approval between steps — the user repeatedly says «ادامه بده» and means it; only stop for genuine blockers or decisions that truly need them, and always report measured outcomes after each step (never a textless turn).
3. **Sync after EVERY change** to `VOID_CLUB_PROJECT/` and `VOID_CLUB_CLOUD_DEPLOY/` — BUT diff first, sync is bidirectional. The user hand-edits files inside `VOID_CLUB_PROJECT/frontend/` (seen: padding tweaks in `payment-callback.html`, an extra `category_id` line in `js/products.js`). Before copying root→targets, run `diff -rq frontend VOID_CLUB_PROJECT/frontend --exclude=uploads --exclude=*.db`; if PROJECT has unique lines, merge them into the root copy FIRST, then copy root→both targets, then verify `diff -rq` = 0 against BOTH targets. A blind one-way copy silently deletes the user's manual edits.
   There are FOUR live frontend copies: root `frontend/`, `VOID_CLUB_PROJECT/frontend/`, `VOID_CLUB_CLOUD_DEPLOY/frontend/`, plus the PHP port `VOID_CLUB_CPANEL/` (and three FastAPI backends + the PHP `api/`). A feature present in only ONE copy is NOT done — the user's «still old version / not slider on my phone» always means they opened a non-patched copy (seen 2026-09-11: new-arrivals slider shipped in CPANEL only while root/PROJECT/CLOUD still had the 4-item grid). Acceptance before claiming done: grep the feature's anchor strings in ALL FOUR frontends and require matching counts.
4. **There is no git repo in the project root** — no history to roll back to; rollbacks are manual reverse-patches. Therefore keep every patch call SMALL (under ~8K tokens). Oversized patch calls time out mid-stream and leave half-applied state. Prefer many small patches over one large one, and batch independent file edits across separate calls.

## Running & verifying

- Start: `.venv/Scripts/python.exe run_server.py` (background terminal). Health: `GET /` , `/api/products`, `/account.html` → 200.
- **Backend edits REQUIRE a full uvicorn restart.** A stale process silently serves the old route table and causes `405 Method Not Allowed` even though the code is correct. Kill the old PID, restart, then verify.
- Verify routes against the LIVE server's `/openapi.json`, not against the source files — the running process is the truth.
- Test browser flows with `browser_exec` against `http://127.0.0.1:8000` before claiming done. `browser_exec` patterns that work: first line of `code` must be a plain `# comment` step label; helpers (`new_tab`, `goto_url`, `wait_for_load`, `page_info`, `js`) are pre-imported bare — never `from agent_helpers import ...` (ModuleNotFoundError). Never wrap `js()` in `new Promise` + `setTimeout` (harness throws `Unexpected end of input`); instead split into separate `browser_exec` calls with Python `time.sleep()` between them. Inside `js('...')` you write JavaScript, not Python — use `.trim()`, never `.strip()` (throws `...strip is not a function` and fails the whole call, seen 2026-09-19). After each verification call, report the measured numbers in chat — never fire tool calls with an empty response.
- **HARD RULE — no textless turns, EVER.** The harness silently drops any assistant turn that contains ONLY tool calls (user sees it as «قطع شدی», seen ~10× in one session). Every tool batch MUST carry a short Persian status line saying what the batch does, and every tool result MUST be answered with its measured outcome in chat before the next batch. A `terminal`/`browser_exec`/`patch` call with zero accompanying message text is a lost turn — always attach the one-liner.
- **Guide anchor-scroll offset (`guide.html` sidebar + footer deep links): single source of truth is CSS.**
  - `.guide-card { scroll-margin-top: ... }` must clear the UNSCROLLED header bottom (measured live: `.site-header` top:48 + height:69 = 117px bottom, announcement 38px) plus breathing room — 135px desktop / 115px mobile worked. The header SHRINKS on scroll (`.scrolled`: top 48→10, bottom 117→79 via `ui.js initHeaderScroll`), so any JS offset measured at click time (unscrolled) overshoots every section except `#sizes`.
  - NEVER call `history.replaceState(null,'','#'+id)` inside the anchor click handler: it makes the browser think the hash already changed, which CANCELS the native jump (symptom: `scrollY` stays 0, only the URL hash changes). Let the native jump do both scrolling and hash update; JS only tracks `active` class + scroll-spy.
  - NEVER do manual `window.scrollTo(y = rect.top + pageYOffset - measuredHeader)` for these links for the same shrinking-header reason. No `scrollIntoView` overrides either — native jumps already respect `scroll-margin-top`.
  - If clicks land nowhere, first check whether some global handler calls `preventDefault`/`replaceState` on the anchors before suspecting CSS.

## Known pitfalls (class-level)

- **Admin Subtab & Panel Switching (`app.js`, `account.html`)**: `switchAccountPanel(panelName, navItem)` must explicitly trigger data loading for the activated panel (`admin` -> determine active subtab and invoke `switchAdminSection(activeSection)`, `orders` -> `loadUserOrders()`, `addresses` -> `loadUserAddresses()`). Furthermore, `switchAdminSection(sectionName, tabBtn)` must explicitly call the data loader for that section (`loadAdminStats`, `loadAdminProducts`, `loadAdminCategories`, `loadAdminBanners`, `loadAdminOrders`, `loadAdminUsers`), rather than only toggling container visibility (`display: block`).
- **CRITICAL: Admin Scripts & Stylesheets Must Remain Statically Loaded (`account.html`, `checkout.html`) — Never Make them Asynchronous (session 2026-09-22):** Automated audit tools often suggest dynamically loading `enterprise-admin.js` and admin CSS (`admin-responsive.css`, `enterprise-admin-full.css`, `invoice-print.css`) only after checking `auth.isAdmin()`. **DO NOT DO THIS.** In this vanilla JS architecture, `app.js` runs on `DOMContentLoaded` and relies on `enterprise-admin.js` having already executed and bound its functions to `window`. Dynamically injecting `enterprise-admin.js` causes a fatal race condition where `app.js` executes first, breaking all admin tabs, products table, and batch tools wholesale («پنل ادمین خراب شد کلا»). Keep admin CSS in `<head>` and `enterprise-admin.js` statically deferred immediately BEFORE `app.js`. Full triage pattern in `references/third-party-audit-triage.md`.
- **Banner Quick Link Pickers in Admin (`app.js`)**: In `loadAdminBanners()`, ensure categories and products are queried to populate `allBannerCategoriesCache` and `allBannerProductsCache`, and invoke `handleBannerSearchLinks('')` to render the quick-select listboxes (`#adm-b-quick-category`, `#adm-b-quick-product`) so admins can set banner target URLs without typing.
- **Checkout & Order Creation Flow (`checkout.html`, `app.js`, `orders.py`)**: `initCheckoutPage()` formats cart items as `[{product_id, variant_id, quantity, price}]` and sends to `POST /api/orders` along with `shipping_address_id`. Order numbers are formatted as `VOID-XXXXX`. Ensure `checkout.html` script tags use cache-busting queries (`?v=...`) to avoid stale cart/order payloads.
- **Global JS Scope, TDZ & Cache Busting in Vanilla Frontend**: 
  - **Cross-file duplicate top-level declarations are FATAL.** All `<script src>` files share ONE global scope (no modules). If two files declare the same top-level name with `let`/`const` (e.g. `uploadedProductGalleryImages` was declared in both `enterprise-admin.js` and `app.js`), the browser throws `Identifier '...' has already been declared` and **the ENTIRE second script silently never executes** — no `window.*` bindings, no `initRouter`, admin link stays hidden, profile stays empty, all buttons dead. When the admin panel suddenly breaks wholesale, FIRST check: extract the served JS and `eval()` it (or check console) for declaration collisions, and diff top-level `let/const/var/function` names across `frontend/js/*.js` with a script before anything else. Guard shared state with `var x = window.x || ...` / `if (typeof x === 'undefined')` patterns or declare it in exactly ONE file.
  - All shared state and cache arrays (`currentAdminOrdersCache`, `currentUserOrdersCache`, `currentUserAddressesCache`, `editProductImagesList`, etc.) MUST be declared at the TOP of `app.js` before `initRouter()` or any loader function executes; declaring them mid-file with `let` causes JavaScript *Temporal Dead Zone (TDZ)* errors (`Cannot access '...' before initialization`) when `initAccountPage()` runs on startup.
  - All handlers invoked via inline HTML attributes (`onclick`, `onchange`, `onsubmit`, such as `openEditProductModal`, `closeEditProductModal`, `handleSaveProductEdit`, `handleEditProductUpload`, `setEditProductHoverImage`, `switchAdminSection`, `switchAccountPanel`, `handleToggleUserAdmin`, `handleCreateBanner`, `handleSaveAddress`, `handleSaveUserProfile`) MUST have their concrete function definitions in place AND be explicitly bound to `window` in `app.js` / `enterprise-admin.js`.
  - All modal overlays (`.modal-overlay`, `.invoice-modal`) should have backdrop click handlers (`if (e.target === modal) modal.classList.remove('open')`) registered on init.
  - In HTML files, increment script cache busting queries across all pages (`js/app.js?v=3.0`, `js/enterprise-admin.js?v=3.0`) so frontend browsers immediately pick up script updates without stale cache collisions. On a REVERT/rollback, still bump the version FORWARD (never restore the old number) — otherwise browsers keep serving the reverted-away code from cache and the rollback silently never lands.
- **Silent dead handlers — bare method references without `()` (`ui.js`, `app.js`, `sr7-slider.js`, `login.html`).** A method named without call parens (`openSearch;`, `() => this.closeCart`, `str.toLowerCase`, `lower.includes`, `onclick="addCurrentProductToCart"`) is valid JS — `node --check` passes, zero console errors — but the call never fires and the button/handler is silently dead. Seen 2026-09-10 (~25 instances): dead search button on all pages, unclosable drawers, product page stuck on «خطا در دریافت مشخصات محصول» while the API returned 200. When a button "does nothing" with a healthy API, run the dead-handler sweep BEFORE suspecting fetch/routing — commands, false-positive list, and the render-path diagnosis rule live in `references/dead-handler-sweep.md`.
- **Multi-Agent Verification & Delegation Workflow**: For multi-area regressions (addresses, orders, admin subtabs), organize work explicitly with the `todo` tool, spawn 3 parallel subagents via `delegate_task` to inspect and repair specific domains concurrently, and follow up with a holistic end-to-end integration test before concluding.
- **Port 8000 Socket Conflict (`Errno 10048`) & Server Lifecycle**: Lingering Python/Uvicorn processes on Windows will lock port 8000. `start.bat` should auto-release port 8000 before launching Uvicorn, and any server restart must ensure previous python processes bound to 8000 are killed (`Stop-Process` / `taskkill`).
- **Product Image Gallery & Card Hover Logic (`account.html`, `app.js`, `components.css`)**:
  - In the admin product edit modal, `editProductImagesList` maintains image order: index 0 is Main (`is_featured = true`), index 1 is Hover Image slot, with quick "Set Main" (⭐) and "Set Hover" (✨) buttons and direct upload via `api.upload(file, true)`.
  - **CRITICAL Storefront Card Hover Pitfall — NEVER blindly use `images[1]`**: Previously, storefront cards did `const hoverImg = p.images?.[1]?.url || featImg;`. This causes the infamous "hover image broken / main image shows as background overlay" bug whenever: (1) a product has only 1 image, so two identical `<img>` tags stack on top of each other and hover transitions opacity over identical pixels; (2) `is_featured` is reordered such that index 1 matches `featImg`; or (3) an upload is a video file (`.mp4/.webm`) placed in an `<img>` tag.
  - **Correct pattern (`getCardImages(p)` + `cardMediaTag(...)`)**:
    - `featUrl`: `images.find(i => i.is_featured)?.url || images[0]?.url`.
    - `hoverUrl`: `images.find(i => i.url && i.url !== featUrl)?.url`.
    - `hasHover`: `Boolean(hoverUrl && hoverUrl !== featUrl)`.
    - If `!hasHover`, do NOT render `.product-card-img-hover` at all.
    - Add `onerror="this.style.display='none'"` on hover media so broken URLs don't break the card.
    - Use `<video>` tags for video URLs (`.mp4/.webm/.mov`).
    - In CSS (`components.css`), add `@media (hover: none) { .product-card-img-hover { display: none !important; } }` so touch devices never get stuck on the hover image.
    - **Blank-card root cause on touch (session 2026-09-12):** that `display:none` rule COMBINED with an unguarded `.product-card:has(.product-card-img-hover):hover .product-card-img { opacity: 0 }` blanks the whole card on touch — after a tap `:hover` sticks, the main image fades to 0 while the hover image stays `display:none`, leaving only the halo background. No JS (touch/pointer/mouseenter) is involved; it is pure CSS. Fix: wrap ALL hover-swap rules (main-image scale, main `opacity:0`, hover `opacity:1`) in `@media (hover: hover) and (pointer: fine) { ... }` so touch devices never change image opacity at all. Never fix it with an `opacity: 1 !important` hack. Desktop hover behavior stays byte-identical inside the guard.
- **Product Sizes & Stock Are Variant-Level — Never Hardcode the Size List (`products.py`, `app.js`, `account.html`)**: sizes/stock live in `ProductVariant(size, color, stock)`; the product page already renders size buttons from `product.variants`. But both admin flows (`handleAdminAddProduct`, `handleSaveProductEdit`) hardcoded `sizes = ['S','M','L','XL','2XL','3XL']` with fixed stock (20/50), so the admin had zero size control. Any size UI must READ sizes from `product.variants` and WRITE explicit `variants: [{size, color, stock}]` payloads (checkbox + per-size stock input in both the add form `#admin-add-product-form` and the `#edit-product-modal`, pre-ticked from existing variants on edit). Never hardcode a size array in JS.
- **Mobile Hero Slider (`sr7-slider.css`, `sr7-slider.js`)**: Always maintain `aspect-ratio: 16 / 9` (or `height: auto`) on mobile screens rather than forcing fixed `height: 60vh` / `min-height`, which zooms and crops character artwork. Slider supports video (.mp4, .webm, .mov) via `<video muted playsinline preload="auto">` (NO `loop`, NO `autoplay` attr — playback driven from JS) and GIFs alongside static images. Timing is PER-SLIDE via `banners.duration` (seconds, default 6, clamp 1..60): timeout-chain (`setTimeout` per slide, never `setInterval`), images shown exactly `duration`, long videos CUT at `duration`, short videos advance early via per-slide `ended` listener + `loadedmetadata` shrink. In `sr7GoTo(index)`, active video: `muted=true; currentTime=0; loop=(slides.length<=1); play()`; inactive: `pause()` + detach `_sr7EndedHandler`. Bullet progress synced via `--sr7-dur` CSS var (`animation: sr7-progress var(--sr7-dur,6s)`). Full recipe: `references/banner-duration.md`.
- **Responsive hero banners — separate desktop/mobile asset (`mobile_image_url`, session 2026-09-16).** Mobile must NEVER download the desktop video: (1) DB — `banners.mobile_image_url VARCHAR(500) NULL` in `api/schema.sql` + SQLite mirror in `vc_sqlite_init()` + `vc_ensure_banner_mobile($pdo)` auto-migration (SELECT-probe then ALTER, sqlite vs MySQL branches) + expose in `vc_banner_public()` with fallback to `image_url` when empty; (2) API — `POST`/`PUT /banners` whitelist `mobile_image_url` (empty string → NULL; blank PUT = leave unchanged); (3) admin (`account.html` + `app.js`) — two upload boxes (desktop 16:9 required, mobile 9:16/1:1 optional, each with own file input + `handleBannerDirectUpload(files, targetInputId)`), list preview renders BOTH thumbnails (desktop 140px 16:9 + mobile 90px 9:12) with per-variant video detection `/\.(mp4|webm|mov|m4v)(\?.*)?$/i`; (4) slider (`sr7-slider.js`) — `sr7PickUrl(b)` via `matchMedia('(max-width: 768px)')`, `data-desk`/`data-mob` attrs on every slide, `change` listener swaps the ACTIVE slide src live on breakpoint cross + restarts autoplay, first slide eager (`fetchpriority=high`) + rest lazy (`preload=none` + `data-sr7-src`, activated in `sr7GoTo`). Acceptance: phone loads only the mobile file (verify via network), desktop only the desktop file, rotation swaps without reload.
- **Server-side order archive (`is_archived`, session 2026-09-16, updated 2026-09-17).** Never use `localStorage` for archive state (lost across devices/browsers — the old `void_archived_orders` bug):
  - (1) DB: `orders.is_archived TINYINT(1) DEFAULT 0` + `ix_order_archived` index in `schema.sql`, SQLite mirror + `vc_ensure_order_archived($pdo)` auto-migration, expose bool in `vc_order_full()`.
  - (2) API: `GET /orders?archived=1|0` filter (`COALESCE(is_archived,0)=0` for active) + `PUT /orders/:id/archive` admin-only with `{archived:bool}` (missing key = archive).
  - (3) Frontend Admin Panel: `loadAdminOrders()` fetches with `showArchivedOrders` toggle, `handleArchiveOrder()` PUTs then refreshes both admin and user lists, rendering `isArchived = !!o.is_archived`.
  - (4) Customer View «سفارش‌های من» (`loadUserOrders` & `renderUserOrdersList`): For admins, `GET /orders` returns ALL orders in the DB. `loadUserOrders()` must filter to own `user_id`, AND `renderUserOrdersList()` MUST filter `currentUserOrdersCache` by `showUserArchivedOrders ? isArch : !isArch` (default active only). Without this, archived orders keep showing up on refresh and the user reports "آرشیو کار نمی‌کنه و خرابه".
  - (5) Dual-action button: in both views, order cards render a dual-state button: if active, yellow "آرشیو سفارش" (`fa-box-archive`); if archived, green "بازگردانی از آرشیو" (`fa-arrow-rotate-left`). `handleArchiveUserOrder` and `handleArchiveOrder` toggle `archived: !isCurrentlyArchived` and sync both `currentUserOrdersCache` and `currentAdminOrdersCache` in place.
- **Admin logged in as customer — «My Orders» must be filtered to own `user_id` and archive state (session 2026-09-16, updated 2026-09-17).** Both `loadAdminOrders()` and `loadUserOrders()` hit `GET /orders`, and because the caller `is_admin`, the API returns EVERYONE's orders — so «سفارش‌های من» fills with other customers' orders unless filtered. Rule: `renderUserOrdersList()` filters `currentUserOrdersCache` to `o.user_id === auth.getUser()?.id` AND separates active vs archived orders via `showUserArchivedOrders` toggle. Non-admin `GET /orders` already adds `AND COALESCE(is_archived,0)=0` so an admin-archived order disappears from customer view automatically.
- **PageSpeed & Core Web Vitals standard checklist (session 2026-09-17).** When optimizing mobile performance (51 → 85+):
  - (1) Logo/emblem downscaled from 3162px to 500px retina (~33KB vs 555KB, 94% network reduction) and `width="28" height="28"` explicitly set on `<img>` to eliminate CLS;
  - (2) Remove `@import` from `variables.css`, add `preconnect` to `fonts.googleapis.com` & `fonts.gstatic.com` + direct `<link ... display=swap>` in `<head>` (prune weights to 400, 600, 700, 800);
  - (3) Icon CSS (RemixIcon, FontAwesome) is now SELF-HOSTED — `assets/icons/remixicon.css` + `fa-all.css` with fonts in `assets/webfonts/`. The old CDN + `media="print" onload="this.media='all'"` lazy pattern is BANNED: behind Iranian filtering the CDN stylesheet never arrives and `onload` never fires, so icons vanish permanently with zero console errors (fixed 2026-09-18 after «آیکون ها لود نمی شن»). See the Icon architecture subsection below;
  - (4) Add `defer` to all `<script src="...">` tags at the bottom of all HTML pages to cut Total Blocking Time (TBT);
  - (5) **Slider multi-video eager preload bug:** In `sr7-slider.js` within `sr7GoTo`, guard `video.setAttribute('src', wantUrl)` and `video.load()` inside `if (isActive)`. Never call `video.load()` inside `slides.forEach` on inactive slides, or mobile downloads all videos (8+ MB) simultaneously on page load;
  - (6) **Touch hover image suppression:** In `js/app.js` within `cardMediaTag`, check `window.matchMedia('(hover: none)').matches` and return `''` for hover images on touch devices. Even when hidden by CSS, mobile Chrome prefetches lazy images within scroll margin, downloading 10+ MB of invisible hover images. Always bump `variables.css?v=` and `app.js?v=` forward across all HTML files after edits. Details in `references/pagespeed-optimization.md`.
- **Unclosed `<style>` or `<head>` Tags Swallowing Entire Page Body (session 2026-09-18):**
  When inlining critical CSS or modifying `<head>`, omitting `</style>` or `</head>` before `<body ...>` causes the browser to parse all subsequent HTML (entire body, headers, products, scripts) as CSS rules. The browser renders a completely blank black screen and reports zero interactive DOM elements. Always run a tag balance check (`head`, `style`, `body` open vs close counts) across all `.html` pages and physically verify with `open_preview` + `drive_preview(action='elements')` before claiming pages are ready.
- **Stray `</div>` inside the banner form leaks `#admin-banners-list` into every admin tab (session 2026-09-16).** Symptom: the delete-banner button row renders above Users, Orders, and all other admin sections. Root cause: an extra closing `</div>` before the link-picker `form-group` closed `#admin-add-banner-form` early, so the form's remaining fields AND the `#admin-banners-list` container ended up outside `admin-sec-banners` (which `switchAdminSection` hides per-tab). Diagnose with a tag-balance script (HTMLParser tracking `div/form/select/table/button/section`, report unclosed/stray tags with line numbers) — zero errors is the acceptance check. Never re-patch section JS when the layout bleeds across tabs; check form tag balance first.
- **Banner edit in-place — never delete/recreate (session 2026-09-16).** Pattern: hidden `#adm-b-edit-id` in the form + `#adm-banner-cancel-btn` (hidden unless editing); each banner row gets an edit button that fills the form (title/subtitle/desktop+mobile URLs/link/CTA/duration), sets the hidden id, shows cancel, and scrolls to the form; submit branches — id present → `PUT /banners/:id` (mobile empty string → NULL, blank duration = leave unchanged), else `POST /banners`; after either, `cancelBannerEdit(true)` + form reset + `loadAdminBanners()`. Bump `js/app.js?v=` forward in ALL pages after touching banner logic.
- **Storefront load performance triage (session 2026-09-16).** When "site loads slow" is reported, measure before patching: `du` on `uploads/` (seen: ~30MB, several 3–4MB PNGs — the #1 cause), then apply in order: (1) slider lazy-activate — first slide eager (`fetchpriority="high"`, `preload="auto"`), rest `preload="none"` + `data-sr7-src` activated in `sr7GoTo` (+ `video.load()`); (2) `Cache-Control: public, max-age=30` on `GET /products` list + `max-age=60` on `GET /banners`; (3) `preconnect` + `dns-prefetch` for `cdn.jsdelivr.net` / `cdnjs.cloudflare.com` in `<head>`; (4) forward `?v=` bumps on every touched JS in ALL pages after any logic change. The durable fix for multi-MB PNGs is a one-shot WebP conversion of `uploads/` (offer it, don't silently recompress user art).

### Persian Mojibake Recovery (Windows-1256 / UTF-8 corruption)
- **Symptom:** Persian text suddenly renders as garbled Latin/Arabic characters like `ظپط±ظˆط´ع¯ط§ظ‡` (instead of `فروشگاه`), `ط¯ط±ط¨ط§ط±ظ‡` (instead of `درباره`), `ظ…ط­طµظˆظ„` (instead of `محصول`).
- **Root Cause:** A tool or editor read UTF-8 Persian bytes through the Windows-1256 codepage and re-saved them as UTF-8 (often with a `\ufeff` BOM).
- **100% Lossless Recovery Recipe:**
  ```python
  with open(filepath, 'r', encoding='utf-8-sig') as f:
      corrupted_text = f.read()
  recovered_text = corrupted_text.encode('windows-1256').decode('utf-8')
  with open(filepath, 'w', encoding='utf-8') as f:
      f.write(recovered_text)
  ```
  This cleanly restores all original Persian characters, HTML tags, and attributes. Always backup before running and verify with a regex sweep for `ظپط±|ط®ط±غŒط¯|ط¯ط§ط±ع©`.

- **RTL Horizontal Slider Navigation Scroll Direction (`ui.js`, `app.js`, session 2026-09-23):**
  - In modern browsers with Persian/Arabic `<html dir="rtl">`, horizontal scrolling flows from Right to Left. Initial `scrollLeft` is 0 at the rightmost position.
  - Advancing forward ("بعدی" / leftward progression) requires a **negative scrollBy delta** (`track.scrollBy({ left: -delta, behavior: 'smooth' })` or `track.scrollLeft -= delta`).
  - Returning backward ("قبلی" / rightward progression) requires a **positive scrollBy delta** (`track.scrollBy({ left: delta, behavior: 'smooth' })` or `track.scrollLeft += delta`).
  - Passing positive delta for "next" mistakenly scrolls backwards to the start or gets stuck at 0.
- **Cart Drawer Z-Index Stacking Context & Bottom Sticky Elements Collision (session 2026-09-23):**
  - **The Bug:** On mobile product detail pages (`product.html`), opening the cart drawer revealed that the PDP mobile sticky buy bar (`#pdp-sticky-buy-bar`) was floating ON TOP of the cart drawer. ## Local dev harness for the PHP port — `start.bat` + `router.php` + SQLite (session 2026-09-11)

`VOID_CLUB_CPANEL/start.bat` lets the user double-click to test everything locally:
no MySQL, no cPanel, and cPanel behavior stays byte-identical.

- `router.php` (docroot) mimics `.htaccess` under `php -S`: `/api/<path>` →
  `require api/api.php` with `$_GET['path']` set; existing static files `return false`;
  directory-index + `404.html` fallback included.
- `api/lib_db.php` `vc_pdo()` branches on `VC_DB_DRIVER=sqlite` env →
  `PDO('sqlite:' . (VC_SQLITE_PATH ?: VC_ROOT/data/voidclub.sqlite))` +
  `PRAGMA foreign_keys=ON` + `vc_sqlite_init()` (CREATE TABLE IF NOT EXISTS mirrors
  of `schema.sql` with SQLite-relaxed types, run on every connect). The MySQL path
  is otherwise untouched.
- `install.php` is portable: skips the MySQL-only `schema.sql` import when
  `VC_DB_DRIVER=sqlite` (tables already exist from `vc_sqlite_init()`), seeds via the
  same `seed_void_club()`, and uses `vc_set_setting()` for the shipping-rate default.
- `start.bat` flow: find `php` on PATH → else one-time download of portable PHP 8.3
  NTS zip into `tools/php` + generated `php.ini` enabling `pdo_sqlite, sqlite3,
  mbstring, gd, curl, openssl, fileinfo` → warn if `pdo_sqlite` still missing →
  set `VC_DB_DRIVER=sqlite` + `VC_SQLITE_PATH` → pick first free port
  (8000 → 8080 → 8001) → first run (no sqlite file yet) opens `install.php`,
  later runs open `index.html` → `php -S 127.0.0.1:%PORT% router.php`.
- Portability rule for any future shared-code change: `ON DUPLICATE KEY UPDATE` is
  MySQL-only — never use it in code paths that also run on sqlite; always go through
  `vc_set_setting()` / `vc_get_setting()`. Keep column names 1:1 with `schema.sql`
  and add the SQLite mirror table in `vc_sqlite_init()`.
